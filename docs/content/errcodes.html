Error Codes

The compiler emits structured diagnostics with stable codes. Use the code to look up the cause.

Syntax errors (VNE-001 – VNE-014)

Code Meaning
VNE-001 Unexpected token
VNE-002 Missing semicolon
VNE-003 Unknown type name
VNE-010 Warnings enabled
VNE-011 Dynamic casting enabled
VNE-012 Memory limit enabled
VNE-013 Unknown ruleset flag
VNE-014 Ruleset value expected

Ruleset diagnostics (VNE-015 – VNE-032)

Emitted when a ruleset is applied. These are informational notes, not errors.

Parser extensions (VNE-040 – VNE-050)

Code Meaning
VNE-040 Malformed type parameter list on interface
VNE-041 Nested generic in type parameter position
VNE-042 Malformed type parameter list on function
VNE-043 Nested generic in function type parameter
VNE-050 Malformed region.commit — expected "commit" after "region."

Reading a diagnostic

Every diagnostic in the terminal is printed with:

  • The severity (error, warning, note, perf hint).
  • The error code, which you can look up here.
  • The message text.
  • The source location, in file:line form.
  • A three-line excerpt from the offending file with a caret pointing at the column.
  • Zero or more suggestions, when the compiler has a specific fix in mind.

If you see an error that is not in this list, please open an issue — an undocumented error code is a bug in the documentation, not in your code.
